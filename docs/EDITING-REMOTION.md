# Editing: η μηχανή Remotion — Lambda ή Cloud Run, και η άδεια

Γραμμένο 2026-10-30, Κομμάτι 1 της οδηγίας «18. EDITING: ΛΕΙΤΟΥΡΓΙΚΟ, ΜΕ
ΜΗΧΑΝΗ REMOTION». **Αντικαθιστά την πρόταση του `docs/EDITING-RENDER.md`**
(ffmpeg σε Vercel Fluid / Cloud Run job) — βλέπε το σημείωμα στην κορυφή
εκείνου του αρχείου. Η μηχανή μοντάζ δεν είναι πια ffmpeg απευθείας: είναι
το **Remotion** (βίντεο γραμμένο σε React). Η προεπισκόπηση παίζει
δωρεάν στον browser (Remotion Player) από σύνθεση React· η τελική
εξαγωγή τρέχει στον server, από την ίδια σύνθεση. Η ερώτηση εδώ είναι
ΜΟΝΟ πού τρέχει αυτός ο server: **Remotion Lambda** (AWS) ή **Remotion
Cloud Run** (Google). Η μηχανή είναι κοινή — θα τη χρησιμοποιήσουν και
το Image (Animate), το Video, τα Films και τα Posts — άρα η επιλογή εδώ
είναι απόφαση για όλο το προϊόν, όχι μόνο για το Editing.

## Μέθοδος και περιορισμός δικτύου

Το δίκτυο αυτής της δουλειάς μπλοκάρει απευθείας αίτημα σε
`remotion.dev` και κάθε subdomain του (`www.`, `v3.`, `v4.`,
`cloudrun.`, `convert.`). Οι παρακάτω αριθμοί προέρχονται είτε από
`raw.githubusercontent.com` (το ίδιο το αρχείο `LICENSE.md` — αυτό
διαβάστηκε **αυτολεξεί**), είτε από αναζήτηση ιστού που παραθέτει
κατά λέξη τις επίσημες σελίδες του Remotion, είτε από
`cloud.google.com/run/pricing` (διαβάστηκε απευθείας, ζωντανά). Κάθε
γραμμή παρακάτω λέει ποιο από τα τρία είναι. Βρέθηκαν **2026-10-30**.
Όσα σημειώνονται «μέσω αναζήτησης» αξίζει να ξανακοιτάχτούν από
σύνδεση χωρίς αυτό το μπλοκάρισμα πριν κλειδώσει αριθμός σε τιμή προς
τον χρήστη.

## Ο πίνακας: Lambda έναντι Cloud Run

| | **Remotion Lambda (AWS)** | **Remotion Cloud Run (Google)** |
|---|---|---|
| **Κόστος** | Δεν έχει δική του τιμή — χρεώνεται απευθείας το AWS Lambda του λογαριασμού. Το ίδιο το Remotion δίνει έτοιμο παράδειγμα: **~$0,021** για βίντεο 1 λεπτού, **~$0,162** για 10 λεπτά απομακρυσμένο HD (2048 MB, us-east-1) — *αυτολεξεί, remotion.dev/docs/lambda/cost-example*. Δεν μετράει S3/bandwidth/άδεια. | Το Remotion δεν δίνει έτοιμο παράδειγμα — μόνο «οι περισσότεροι χρήστες βγάζουν πολλά λεπτά βίντεο για λίγα σεντς» — *μέσω αναζήτησης, remotion.dev/docs/cloudrun*. Υπολογισμένο εδώ (όχι επίσημο) στην προκαθορισμένη ρύθμιση 2 GiB/1 vCPU, on-demand τιμολόγηση Google: **≈$0,0017 ανά λεπτό μηχανής** — *cloud.google.com/run/pricing, διαβάστηκε ζωντανά 2026-10-30*. Αυτό είναι λεπτό *μηχανής*, όχι λεπτό *βίντεο* — ίσα μόνο αν τρέχει σε πραγματικό χρόνο, κάτι που το Remotion δεν υποσχέται για το Cloud Run. |
| **Μέγιστη διάρκεια** | Το όριο μίας κλήσης Lambda είναι 900 s (το Remotion προτείνει ≤120 s), **αλλά** το Remotion σπάει το βίντεο σε κομμάτια και τα τρέχει παράλληλα σε πολλές κλήσεις — άρα δεν υπάρχει πρακτικό ανώτατο όριο διάρκειας βίντεο, μόνο όριο **200 παράλληλων Lambda ανά εξαγωγή** και ελάχιστο κομμάτι 4 καρέ. Το όριο ταυτόχρονων εκτελέσεων του ίδιου του AWS λογαριασμού (προκαθορισμένο 1000) μπορεί να το περιορίσει περαιτέρω — *αυτολεξεί, remotion.dev/docs/lambda/checklist, /deployfunction*. | **Σκληρό όριο 60 λεπτών (3600 s), χωρίς καμία λύση.** Το Remotion δεν χωρίζει σε κομμάτια στο Cloud Run (δεν κάνει «distributed rendering» εκεί) και δημοσιεύει μόνο σε Cloud Run **services**, όχι σε Cloud Run **Jobs** του Google που θα επέτρεπαν μεγαλύτερη διάρκεια — *αυτολεξεί, remotion.dev/docs/cloudrun, /cloudrun/limits, /cloudrun/deployservice*. |
| **Ταχύτητα** | Η ρητή δήλωση του Remotion: «Remotion Lambda is the fastest option, because it implements distributed rendering». Όσο μεγαλύτερο το βίντεο, τόσο μεγαλύτερη η διαφορά — *αυτολεξεί, remotion.dev/docs/compare-ssr*. | Η ίδια σελίδα λέει ρητά: «Cloud Run... do[es] not support distributed rendering, so rendering happens on one physical machine» — μία μηχανή, σειριακά, όσο μεγάλο και να είναι το βίντεο — *αυτολεξεί, remotion.dev/docs/compare-ssr, /cloudrun/status*. |
| **Ρύθμιση** | IAM policy + ρόλος εκτέλεσης + IAM χρήστης + S3 bucket, όλα με έτοιμες εντολές του ίδιου του Remotion (`npx remotion lambda policies ...`) που παράγουν το ακριβές JSON για την εγκατεστημένη έκδοση — *αυτολεξεί, remotion.dev/docs/lambda/setup*. | Λογαριασμός Google Cloud + χρέωση ενεργή + Service Account με δικό του IAM ρόλο (14 δικαιώματα) + Cloud Storage bucket. Το Remotion δημοσιεύει το δικό του public container image — δεν χτίζεις το δικό σου — *αυτολεξεί, remotion.dev/docs/cloudrun/setup, /permissions*. |
| **Κατάσταση συντήρησης** | Ενεργή — το ίδιο το Remotion δημοσίευσε βελτίωση ταχύτητας το 2026 (`faster-lambda`). | **«Currently not being actively developed»** — αυτολεξεί. Μόνο κρίσιμα bugs διορθώνονται, καμία νέα λειτουργία. Το Remotion λέει ότι σχεδιάζει να προσαρμόσει τη μηχανή του Lambda ώστε να «ενεργοποιήσει distributed rendering» και στο Cloud Run — αλλά αυτό ΔΕΝ υπάρχει σήμερα — *αυτολεξεί, remotion.dev/docs/cloudrun/status*. |

## Η πρόταση: Remotion Lambda

Για τρεις λόγους, και οι τρεις αυτολεξεί από το ίδιο το Remotion, όχι
εκτίμηση δική μου:

1. **Το Cloud Run έχει σκληρό όριο 60 λεπτών χωρίς καμία λύση.** Το
   Editing θέλει να κόβει podcast σε κεφάλαια (Κομμάτι 11) και μεγάλα
   βίντεο σε σύντομα (Κομμάτι 10) — υλικό που μπορεί να είναι πολύ πάνω
   από 60 λεπτά πριν καν φτάσει στην εξαγωγή. Το Lambda δεν έχει αυτό
   το όριο, επειδή σπάει το βίντεο σε κομμάτια.
2. **Το Remotion λέει το ίδιο ότι το Lambda είναι το ταχύτερο**, ρητά
   επειδή κάνει distributed rendering και το Cloud Run όχι. Το ΚΡΙΤΗΡΙΟ
   ΠΟΙΟΤΗΤΑΣ της οδηγίας («βίντεο 60'' εξάγεται σε λιγότερο από 2
   λεπτά») είναι πιο εύκολο να χτυπηθεί με παράλληλη απόδοση παρά με
   μία μηχανή.
3. **Το Cloud Run «δεν αναπτύσσεται ενεργά»** — κρίσιμο για μια μηχανή
   που θα στηρίξει πέντε εργαλεία (Editing, Image Animate, Video,
   Films, Posts). Μια εξάρτηση που ο ίδιος ο κατασκευαστής της λέει ότι
   δεν προχωράει είναι ρίσκο για κοινή υποδομή, όχι μόνο για ένα
   εργαλείο.

Το κόστος δεν αλλάζει αυτή την απόφαση σε καμία ρεαλιστική ποσότητα:
και τα δύο κοστίζουν σεντς το λεπτό. Το Lambda έχει επιπλέον το
πλεονέκτημα ενός **δημοσιευμένου παραδείγματος με συγκεκριμένο αριθμό**
($0,021/λεπτό, $0,162/10 λεπτά) — κάτι που το Cloud Run δεν δίνει καν,
και το προϊόν χρειάζεται έναν αριθμό για το «τιμή πριν» (`docs/TOOL-RULES.md`).

**Ο αριθμός του Lambda δεν είναι σταθερή τιμή.** Η ίδια η σελίδα του
Remotion λέει να μετρηθεί η δική μας σύνθεση, όχι να εμπιστευτούμε το
παράδειγμα — και βρέθηκε παλιότερο, διαφορετικό στιγμιότυπο της ίδιας
σελίδας με άλλους αριθμούς (έκδοση Remotion v4.0.381). Ο πραγματικός
αριθμός μετριέται **την πρώτη φορά που τρέξει αληθινή εξαγωγή εδώ**
(`estimatePrice()`, δικό εργαλείο του Remotion), και αυτή η μέτρηση
αντικαθιστά την εκτίμηση σε αυτό το αρχείο.

## Η άδεια Remotion

**Αυτολεξεί, από το ίδιο το `LICENSE.md`** (διαβάστηκε απευθείας μέσω
`raw.githubusercontent.com`, όχι μέσω αναζήτησης):

> "You are eligible to use Remotion for free if you are: - an
> individual - a for-profit organization with up to 3 employees - a
> non-profit or not-for-profit organization - evaluating whether
> Remotion is a good fit, and are not yet using it in a commercial
> way."

Το όριο είναι **αριθμός ανθρώπων στην εταιρεία, όχι έσοδα**. Πάνω από
3 άτομα: **Company License**, αγοράζεται στο `remotion.pro`.

**Η τιμή πάνω από το όριο βρέθηκε μέσω αναζήτησης, όχι αυτολεξεί, και
δύο πηγές δεν συμφωνούν απόλυτα** — αξίζει ζωντανός έλεγχος πριν
κλειδώσει αριθμός:
- **Creators**: $25/θέση/μήνα, χωρίς ελάχιστο αριθμό θέσεων — για
  χειρωνακτική χρήση χωρίς αυτοματισμό.
- **Automators**: **$0,01 ανά «Render», ελάχιστη χρέωση $100/μήνα** —
  αυτή είναι η κατηγορία που ταιριάζει στο Ionexa: προϊόν που φτιάχνει
  βίντεο αυτόματα, με ενσωματωμένο Player, όχι άνθρωπος σε θέση
  επεξεργασίας.
- **Enterprise**: ελάχιστη χρέωση $500/μήνα (φαίνεται να θέλει επαφή
  πωλήσεων, δεν επιβεβαιώθηκε).

**Σημαντική λεπτομέρεια, αυτολεξεί από τους όρους χρήσης**: η
προεπισκόπηση στο Player/Studio **δεν** μετράει ως «Render» — μόνο η
πραγματική εξαγωγή (Lambda ή Cloud Run) μετράει. Και: *"Free License
Users may build automations without purchasing Renders. The Remotion
for Automators option and its Minimum Spend apply only to Company
License Users."* — δηλαδή όσο η εταιρεία είναι κάτω από το όριο των 3
ατόμων, οι εξαγωγές δεν κοστίζουν τίποτα στο Remotion, αυτόματες ή όχι.
Η κατηγορία Automators ($0,01/render, $100/μήνα) ενεργοποιείται ΜΟΝΟ
αφού χρειαστεί ήδη Company License.

**Από την έκδοση 5.0 του Remotion και μετά, η αναφορά εξαγωγών γίνεται
υποχρεωτική** (χρειάζεται `licenseKey`) για όποιον έχει Company
License — σήμερα είναι προαιρετική.

## ΘΕΛΩ ΑΠΟ ΤΟΝ ΗΛΙΑ

1. **Έγκριση: Remotion Lambda, όχι Cloud Run**, για τους τρεις λόγους
   πάνω. **Μέχρι να απαντήσεις, χτίζω τα υπόλοιπα κομμάτια** (όπως λέει
   η οδηγία) — η επιλογή server δεν μπλοκάρει την οθόνη, τη λήψη υλικού
   από το AI ή τις αλλαγές με λόγια.
2. **Λογαριασμός AWS με κάρτα**, όταν φτάσουμε στο Κομμάτι 11 (τελική
   εξαγωγή). Κόστος σήμερα: €0 — η κάρτα ενεργοποιεί τον λογαριασμό,
   δεν χρεώνεται μέχρι να τρέξει πραγματική εξαγωγή. Δεν μπλοκάρει τα
   κομμάτια 2-10.
3. **Πόσα άτομα έχει σήμερα η εταιρεία**, για να ξέρουμε αν είμαστε
   ακόμα στο δωρεάν όριο του Remotion (έως 3) ή χρειαζόμαστε ήδη
   Company License. Αν χρειαζόμαστε, η κατηγορία **Automators**
   ($0,01/render, $100/μήνα ελάχιστο) είναι αυτή που ταιριάζει, όχι η
   Creators — αλλά αυτή η τιμή βρέθηκε μέσω αναζήτησης, όχι αυτολεξεί
   από το remotion.pro, και αξίζει ζωντανό έλεγχο πριν δεσμευτούμε.
4. Ο μετρητής εξαγωγών στη σελίδα διαχείρισης (`/dashboard/system-health`)
   που ζητά η οδηγία είναι χρήσιμος είτε χρειαζόμαστε άδεια είτε όχι —
   μετρά και τον κίνδυνο κόστους AWS, όχι μόνο τα renders του Remotion.
   **Δεν έχει χτιστεί ακόμα σε αυτό το κομμάτι** — δεν υπάρχει καμία
   πραγματική εξαγωγή να μετρηθεί πριν το Κομμάτι 11, οπότε ο μετρητής
   ανήκει εκεί, όχι εδώ· καταγράφεται ως εκκρεμότητα στο `docs/QUEUE.md`.
