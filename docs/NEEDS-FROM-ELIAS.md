# Τι χρειάζομαι από σένα

Κατά σειρά ανάγκης. Κάθε γραμμή λέει τι ξεμπλοκάρει. Όταν κάτι γίνει,
σβήνεται από εδώ στο ίδιο commit που το χρησιμοποιεί.

## Ανοιχτά

1. **Ένα νέο session στο ίδιο environment**, για να φτάσει το
   `GEMINI_API_KEY`. Οι μεταβλητές διαβάζονται όταν ξεκινά ένα session·
   σε αυτό εδώ δεν υπάρχει.
   *Ξεμπλοκάρει:* τη δοκιμή των 3 cinematic δειγμάτων (1.3).

2. **Όριο κόστους δοκιμών** («[ΠΟΣΟ]» στον τρόπο λειτουργίας): πόσα
   ευρώ ανά δοκιμή και ανά session.
   *Ξεμπλοκάρει:* κάθε δοκιμή που καλεί πληρωμένο πάροχο.

3. **ffmpeg: λύση 1 (μέσα σε Vercel function) ή 2 (Google Cloud Run).**
   Κόστη και κίνδυνοι στην αναφορά της 2026-10-03.
   *Ξεμπλοκάρει:* τα καρέ και τις εκδόσεις κινητού (1.3, 1.4).

4. **Όρια cinematic ανά πλάνο, και το 20%.** Ναι ή όχι στο ανώτατο
   όριο (Starter 7 ΣΤ, Growth 4, Pro 8, Ultimate 16 τον μήνα). Για ≤20%
   σε όλους: margin 6,67× ή χωρίς δωρεάν chat ή μένει 25%;
   *Ξεμπλοκάρει:* τα όρια στον κώδικα (1.3).

5. **Τα κλειδιά να έρθουν και σε αυτό το environment**, με τα ίδια
   ονόματα που έχουν στο Vercel: `DEEPGRAM_API_KEY`, `BFL_API_KEY` (ή
   όπως το ονόμασες), `IDEOGRAM_API_KEY`, `ELEVENLABS_API_KEY`,
   `OPENAI_API_KEY`, `GROQ_API_KEY`.
   - Πού: μενού του cloud environment στον τίτλο του session → Edit →
     environment variables. Όχι στο chat.
   - Γιατί: εδώ δεν μπορώ να δοκιμάσω τίποτα με κλειδί που ζει μόνο στο
     Vercel. Ο έλεγχος εγκυρότητας τρέχει και από τη σελίδα
     `/dashboard/system-health` στην παραγωγή, όταν φτιαχτεί.
   - **Πιο γρήγορα:** στην παραγωγή, `/dashboard/system-health` →
     «Provider keys» → «Check keys». Λέει για κάθε κλειδί αν δουλεύει.
     Πες μου τι γράφει.
   - Τα ονόματα που περιμένει ο έλεγχος: `BFL_API_KEY`,
     `RUNWAYML_API_SECRET`, `GOOGLE_API_KEY` ή `GEMINI_API_KEY`. Αν στο
     Vercel έχουν άλλο όνομα, θα δείξει «not set»· άλλαξε το όνομα στο
     Vercel.
   *Ξεμπλοκάρει:* τη ζωντανή δοκιμή των adapters ήχου και εικόνας (1.0).

6. **Το query για τους πληρωμένους λογαριασμούς**: τρέξε
   `node scripts/db/paying-accounts.mjs --sql`, επικόλλησε το αποτέλεσμα
   στον SQL editor του Supabase και πες μου τα νούμερα.
   *Ξεμπλοκάρει:* το «πρώτα μέτρησε» του 1.1.

7. **Χάρτης/βίντεο σε published site: φαίνονται ή όχι;**
   *Ξεμπλοκάρει:* το 1.7.

8. **BOT_EMAIL / BOT_PASSWORD στα GitHub Actions secrets**: GitHub →
   Settings → Secrets and variables → Actions. Όχι στο Vercel.
   *Ξεμπλοκάρει:* τον e2e-bot και τα 12 🟡 → 🟢 (1.8).

9. **Gmail: απόφαση για την αξιολόγηση CASA.**
   - Το `gmail.readonly` είναι «restricted» scope.
   - Χωρίς έλεγχο από τη Google, μέχρι 100 δοκιμαστικοί χρήστες.
   - Με πραγματικούς χρήστες: ετήσια αξιολόγηση ασφαλείας CASA από
     εργαστήριο που ορίζει η Google. Δευτερογενείς πηγές λένε
     $15.000–75.000 και 4–6 εβδομάδες. Δεν το είδα στη σελίδα της Google.
   - Επιλογές: μόνο Drive/Ημερολόγιο στην αρχή, ή Gmail για ≤100 χρήστες
     σε δοκιμή, ή προϋπολογισμός CASA.
   *Ξεμπλοκάρει:* το 1.9 και το Gmail του Υ6.

10. **GOOGLE_OAUTH_CLIENT_ID / _SECRET στο Vercel** (μετά την απόφαση
    του 9).

11. **Έγκριση σεναρίων εργαλείων.** Θα μπαίνουν εδώ ένα ένα, όταν τα
    γράφω.
