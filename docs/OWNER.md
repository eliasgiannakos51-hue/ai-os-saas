# Εγχειρίδιο για σένα

Για το Ionexa, σε απλά ελληνικά, χωρίς προγραμματισμό. Κάθε ενότητα
είναι μία από τις ερωτήσεις του MASTER, ενότητα Γ (εγχειρίδιο για μένα), με
τα ίδια λόγια.

Πώς διαβάζεται:

- Ό,τι γράφεται μέσα σε « » είναι κουμπί ή τίτλος **μέσα στο Ionexa**, με τα
  λόγια που βλέπεις στην οθόνη.
- Ό,τι γράφεται "έτσι" είναι κουμπί σε **άλλη υπηρεσία** (GitHub,
  Vercel, Supabase, Stripe), όπως το γράφει εκείνη, συνήθως στα αγγλικά.
- Οι σελίδες του Ionexa δίνονται με ολόκληρο σύνδεσμο. Οι σελίδες
  διαχείρισης ανοίγουν μόνο για τα email που είναι στο `ADMIN_EMAILS`·
  για όλους τους άλλους είναι σαν να μην υπάρχουν.

Ο έλεγχος `scripts/tests/owner-manual.test.mjs` αποτυγχάνει αν μια οδηγία
εδώ αναφέρει σελίδα, κουμπί ή αρχείο που δεν υπάρχει πια.

Όπου μια ενότητα λέει **Δεν υπάρχει ακόμα**, το εργαλείο λείπει από το
Ionexa (μετρήθηκε 2026-10-07). Γράφεται τι κάνεις μέχρι τότε.

## Πώς κάνω merge και πώς τρέχω migration

**Merge ενός pull request**

1. Άνοιξε τον σύνδεσμο του pull request που σου στέλνω, π.χ.
   https://github.com/eliasgiannakos51-hue/ai-os-saas/pulls
2. Κάτω κάτω, δες ότι οι έλεγχοι είναι πράσινοι.
3. Αν το pull request γράφει migrations, τρέξε τα **πρώτα** (παρακάτω).
4. Πάτα "Merge pull request" και μετά "Confirm merge".
5. Σε λίγα λεπτά το Vercel ανεβάζει τη νέα έκδοση μόνο του.

**Migration**

Κάθε migration το τρέχεις εσύ, με το χέρι. Αν δεν το τρέξεις, δεν τρέχει
ποτέ, και κανείς δεν το λέει. Οι αναλυτικές οδηγίες, με εικόνες της
σειράς, είναι στο `docs/MIGRATIONS-HOWTO.md`. Σύντομα:

1. Στο pull request, άνοιξε το αρχείο του migration (`supabase/migrations/…`)
   και πάτα "Copy raw file".
2. Άνοιξε https://supabase.com/dashboard → το project σου → "SQL Editor"
   → "+ New query".
3. Επικόλλησε και πάτα "Run".
4. Με τη σειρά που γράφει το pull request, ένα ένα.
5. Για να δεις τι λείπει ακόμα: στο ίδιο "SQL Editor", επικόλλησε αυτό που
   τυπώνει το `npm run db:pending -- --sql` (σου το στέλνω εγώ). Αν δεν
   βγάλει γραμμές, δεν λείπει τίποτα.
6. Ή άνοιξε https://ai-os-saas-five.vercel.app/api/health και κοίτα το
   `schema`: εκεί λέει τι λείπει.

## Πώς γυρίζω πίσω την τελευταία αλλαγή

Τρεις τρόποι, από τον πιο γρήγορο:

1. **Χωρίς deploy, σε δευτερόλεπτα.** Κάθε νέο εργαλείο είναι πίσω από
   διακόπτη. Άνοιξε https://ai-os-saas-five.vercel.app/dashboard/system-health
   → «Διακόπτες» → στον διακόπτη του εργαλείου διάλεξε «Κανείς».
   Ισχύει αμέσως. Οι άλλες δύο επιλογές: «Εσύ και ο λογαριασμός δοκιμής»,
   «Όλοι».
2. **Ολόκληρη η αλλαγή.** Στη σελίδα του pull request που έγινε merge,
   πάτα "Revert" → "Create pull request" → "Merge pull request".
3. **Η προηγούμενη έκδοση του site, όπως ήταν.** Άνοιξε
   https://vercel.com → το project → "Deployments" → η προηγούμενη
   παραγωγή → "..." → "Promote to Production".

Κάθε pull request γράφει στην ενότητα για το πώς γυρίζει πίσω, ποιος από τους
τρεις του ταιριάζει. Οι πίνακες των migrations δεν χρειάζεται να σβηστούν
για να γυρίσει πίσω ο κώδικας.

## Τι κάνω αν το site δεν ανοίγει

1. Άνοιξε https://ai-os-saas-five.vercel.app/api/health
   - Αν δεν ανοίγει καθόλου: το πρόβλημα είναι στο Vercel. Πήγαινε στο 3.
   - Αν γράφει `"ok": false`: το `reason` λέει γιατί (βάση, κλειδιά,
     πολύ παλιά έκδοση).
2. Κοίτα στο GitHub αν υπάρχει ανοιχτό issue με την ετικέτα `ci-red`:
   https://github.com/eliasgiannakos51-hue/ai-os-saas/issues?q=is%3Aopen+label%3Aci-red
   Το ανοίγει μόνο του ο έλεγχος μετά από κάθε deploy, όταν ένα bot δεν
   μπορεί να μπει και να δοκιμάσει την Αρχική, το Chat και ένα εργαλείο.
3. Στο https://vercel.com → το project → "Deployments": αν το τελευταίο
   είναι κόκκινο, κάνε το 3 της ενότητας για το πώς γυρίζω πίσω.
4. Γράψε μου τι είδες. Αν ήταν αλλαγή που έκανες εσύ (κλειδί, ρύθμιση),
   γράψ' την κι αυτήν.

## Τι κάνω αν πέσει ένας πάροχος AI

1. Συνήθως δεν κάνεις τίποτα: αν ένας πάροχος δεν απαντά, το Ionexa
   δοκιμάζει τον επόμενο μόνο του (η σειρά είναι στη ρύθμιση
   `AI_PROVIDER_ORDER` στο Vercel).
2. Για να δεις ποιοι πάροχοι απαντούν: https://ai-os-saas-five.vercel.app/dashboard/system-health
   → «Provider keys» → «Check keys».
3. Αν ένα εργαλείο σπάει εξαιτίας του παρόχου, κλείσ' το προσωρινά: στην
   ίδια σελίδα, «Διακόπτες» → «Κανείς». Αυτό γίνεται μόνο για τα
   εργαλεία που έχουν διακόπτη.
4. **Δεν υπάρχει ακόμα** διακόπτης ανά πάροχο.

## Τι κάνω αν δω απότομη αύξηση κόστους

1. Το Ionexa ελέγχει κάθε ώρα. Όταν βλέπει απότομη αύξηση, ή έναν χρήστη
   να ξοδεύει πολύ περισσότερο από τους άλλους, σου στέλνει ειδοποίηση
   μέσα στην εφαρμογή, και email όταν είναι ρυθμισμένο το `RESEND_API_KEY`.
2. Άνοιξε https://ai-os-saas-five.vercel.app/dashboard/costs και δες
   ποιο εργαλείο και ποιο μοντέλο.
3. Αν είναι ένα εργαλείο: «Διακόπτες» στο
   https://ai-os-saas-five.vercel.app/dashboard/system-health → «Κανείς».
4. Υπάρχει και όριο κλήσεων AI ανά μέρα για όλη την πλατφόρμα, στη ρύθμιση
   `MAX_DAILY_AI_CALLS` στο Vercel. Είναι αριθμός κλήσεων, όχι ευρώ.
5. Βάλε όριο ποσού και στον λογαριασμό του κάθε παρόχου, στη σελίδα
   "Limits" ή "Billing" του καθενός.
6. **Δεν υπάρχει ακόμα** όριο σε ευρώ ανά πάροχο μέσα στο Ionexa.

## Τι κάνω αν διαρρεύσει ένα κλειδί: πώς το ακυρώνω και βγάζω νέο, για κάθε πάροχο

Για κάθε κλειδί, τα ίδια τρία βήματα:

1. Στη σελίδα του παρόχου, από τον πίνακα παρακάτω: φτιάξε **νέο** κλειδί
   και μετά σβήσε το παλιό ("Revoke" ή "Delete").
2. Στο https://vercel.com → το project → "Settings" → "Environment
   Variables": βρες το όνομα, "Edit", επικόλλησε το νέο, "Save".
3. "Deployments" → το τελευταίο → "..." → "Redeploy", για να το πάρει.

| Όνομα στο Vercel | Πού το ακυρώνεις και βγάζεις νέο |
|---|---|
| `ANTHROPIC_API_KEY` | https://console.anthropic.com/settings/keys |
| `OPENAI_API_KEY` | https://platform.openai.com/api-keys |
| `GOOGLE_API_KEY`, `GEMINI_API_KEY` | https://aistudio.google.com/apikey |
| `GROQ_API_KEY` | https://console.groq.com/keys |
| `ELEVENLABS_API_KEY` | https://elevenlabs.io/app/settings/api-keys |
| `DEEPGRAM_API_KEY` | https://console.deepgram.com |
| `UNSPLASH_ACCESS_KEY` | https://unsplash.com/oauth/applications |
| `BFL_API_KEY` | https://api.bfl.ai |
| `IDEOGRAM_API_KEY` | https://ideogram.ai/manage-api |
| `RUNWAYML_API_SECRET` | https://dev.runwayml.com |
| `RESEND_API_KEY` | https://resend.com/api-keys |
| `STRIPE_SECRET_KEY` | https://dashboard.stripe.com/apikeys |
| `STRIPE_WEBHOOK_SECRET` | https://dashboard.stripe.com/webhooks → το endpoint → "Signing secret" → "Roll secret" |
| `SUPABASE_SERVICE_ROLE_KEY`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | https://supabase.com/dashboard → το project → "Project Settings" → "API" |
| `TELEGRAM_BOT_TOKEN` | στο Telegram, στο @BotFather: `/revoke` |
| `SLACK_CLIENT_SECRET` | https://api.slack.com/apps → η εφαρμογή → "Basic Information" |
| `GOOGLE_OAUTH_CLIENT_SECRET` | https://console.cloud.google.com/apis/credentials |
| `VERCEL_API_TOKEN` | https://vercel.com/account/tokens |
| `CRON_SECRET` | δικό σου: ένα νέο μακρύ τυχαίο κείμενο, μόνο στο Vercel |

Δύο εξαιρέσεις, που θέλουν εμένα πριν τις αγγίξεις:

- `INTEGRATION_ENCRYPTION_KEY`: αν αλλάξει, οι συνδέσεις (Gmail, Drive,
  Slack, Calendar) που είναι αποθηκευμένες δεν διαβάζονται πια και ο κάθε
  χρήστης πρέπει να συνδεθεί ξανά.
- `VAPID_PRIVATE_KEY` μαζί με `NEXT_PUBLIC_VAPID_PUBLIC_KEY`: αν αλλάξουν,
  οι ειδοποιήσεις στο κινητό σταματούν ώσπου ο χρήστης να τις ενεργοποιήσει
  ξανά.

Μη στείλεις ποτέ σε κανέναν, ούτε σε μένα, την τιμή ενός κλειδιού.

## Τι κάνω αν χρήστης ζητήσει τα δεδομένα του ή τη διαγραφή τους

Ο χρήστης τα κάνει μόνος του, και έτσι του απαντάς:

1. **Τα δεδομένα του:** https://ai-os-saas-five.vercel.app/dashboard/settings
   → «Εξαγωγή Όλων των Δεδομένων». Κατεβαίνει ένα αρχείο με ό,τι έχει.
2. **Διαγραφή:** στην ίδια σελίδα, «Επικίνδυνη Ζώνη» → «Διαγραφή
   Λογαριασμού». Του έρχεται email με σύνδεσμο, και η διαγραφή γίνεται
   όταν τον πατήσει.
3. Αν δεν μπορεί να μπει στον λογαριασμό του: **Δεν υπάρχει ακόμα**
   εργαλείο για να το κάνεις εσύ για λογαριασμό του. Γράψε μου.
4. Απάντησε μέσα σε έναν μήνα: αυτή είναι η προθεσμία του νόμου (GDPR).

## Τι κάνω αν χρήστης ζητήσει επιστροφή χρημάτων

1. Άνοιξε https://dashboard.stripe.com/payments και βρες την πληρωμή με το
   email του.
2. Πάτα την → "Refund" → διάλεξε όλο ή μέρος του ποσού → "Refund".
3. Αν θέλεις να σταματήσει και η συνδρομή: στο ίδιο μέρος, ο πελάτης →
   η συνδρομή → "Cancel subscription".
4. **Δεν υπάρχει ακόμα**: η επιστροφή στο Stripe δεν αφαιρεί αυτόματα τα
   credits ούτε κατεβάζει το πλάνο στο Ionexa. Γράψε μου ποιον λογαριασμό
   αφορά.

## Τι κάνω αν κάποιος αναφέρει περιεχόμενο που δημοσιεύτηκε

1. Οι αναφορές έρχονται στο email σου, από τη σελίδα επικοινωνίας
   (https://ai-os-saas-five.vercel.app/contact).
2. Άνοιξε τη διεύθυνση που αναφέρει και δες το περιεχόμενο.
3. Αν πρέπει να κατέβει, γράψε μου τη διεύθυνση: **Δεν υπάρχει ακόμα**
   κουμπί για να το κατεβάσεις εσύ. Μέχρι τότε το κατεβάζω εγώ, αφού μου
   το πεις.
4. Απάντησε σε αυτόν που το ανέφερε ότι το είδες.

## Τι κάνω αν κάποιος αναφέρει κενό ασφαλείας

1. Μην το συζητήσεις δημόσια, ούτε σε issue στο GitHub: το repository
   είναι δημόσιο.
2. Το `SECURITY.md` λέει ότι οι αναφορές έρχονται στο security@ionexa.ai
   και ότι απαντάμε μέσα σε δύο εργάσιμες. Απάντησε ότι το λάβαμε.
3. Στείλε μου την αναφορά εδώ, όχι αλλού. Θα σου πω αν είναι κρίσιμο και
   θα το διορθώσω. Σε κάθε δημόσιο κείμενο γράφεται μόνο "διορθώθηκε
   έλεγχος πρόσβασης στο Χ".
4. Αν είναι κρίσιμο, θα σου γράψω **ΚΡΙΣΙΜΟ: κάνε merge τώρα** με τον
   σύνδεσμο.

## Πώς παίρνω αντίγραφο ασφαλείας και πώς κάνω επαναφορά

1. Τα αυτόματα αντίγραφα της βάσης τα κρατά το Supabase, μόνο στα πλάνα
   επί πληρωμή: https://supabase.com/dashboard → το project → "Database"
   → "Backups". Εκεί βλέπεις τις ημερομηνίες και κάνεις επαναφορά με
   "Restore".
2. Πριν από ένα migration που σβήνει κάτι, πάρε αντίγραφο του πίνακα που
   αγγίζει, όπως γράφει το `docs/MIGRATIONS-HOWTO.md`, στην ενότητα 5
   (αντίγραφο ασφαλείας). Η επαναφορά του είναι στην ενότητα 7 του ίδιου
   αρχείου.
3. Ο κώδικας δεν χρειάζεται αντίγραφο: είναι όλος στο GitHub.
4. **Δεν υπάρχει ακόμα** εργαλείο που παίρνει πλήρες αντίγραφο των
   δεδομένων εκτός Supabase, ούτε έχει γίνει δοκιμή επαναφοράς. Ανοιχτό
   στο `docs/NEEDS-FROM-ELIAS.md` (Supabase: αντίγραφα ασφαλείας).

## Πού βλέπω τι κοστίζει και τι βγάζει το Ionexa

- **Τι κοστίζει το AI:** https://ai-os-saas-five.vercel.app/dashboard/costs
  («Κόστη»), ανά εργαλείο και μοντέλο, τις τελευταίες 30 μέρες.
- **Τι βγάζει:** https://ai-os-saas-five.vercel.app/dashboard/business-health
  («Πώς πάει η δουλειά»): έσοδα, συνδρομητές, κόστος AI.
- **Περιθώριο ανά πλάνο:** https://ai-os-saas-five.vercel.app/dashboard/settings
  → «Αναφορά Περιθωρίου».
- **Ποιο μοντέλο απαντά τι:** https://ai-os-saas-five.vercel.app/dashboard/routing
  («Ποιο AI χρησιμοποιείται»).
- **Οι πληρωμές, όπως τις βλέπει η τράπεζα:** https://dashboard.stripe.com/payments
- **Τι χρεώνει ο κάθε πάροχος:** στη σελίδα "Billing" ή "Usage" του
  καθενός.

## Τι κοιτάζω κάθε μέρα σε 2 λεπτά, και τι κάθε εβδομάδα σε 15

**Κάθε μέρα, 2 λεπτά**

1. Οι ειδοποιήσεις και το email σου: ειδοποίηση κόστους από το Ionexa; Αν
   ναι, η ενότητα για την απότομη αύξηση κόστους.
2. https://ai-os-saas-five.vercel.app/api/health: γράφει `"ok": true`;
3. Ανοιχτό issue `ci-red` στο GitHub; (ο σύνδεσμος είναι στην ενότητα για όταν
   το site δεν ανοίγει).

**Κάθε εβδομάδα, 15 λεπτά**

1. https://ai-os-saas-five.vercel.app/dashboard/costs: το κόστος της
   εβδομάδας, σε σχέση με την προηγούμενη.
2. https://ai-os-saas-five.vercel.app/dashboard/business-health: έσοδα και
   συνδρομητές.
3. https://ai-os-saas-five.vercel.app/dashboard/system-health: προειδοποιήσεις
   για κλειδιά, ανοιχτά σφάλματα, και οι «Διακόπτες»: ποιο εργαλείο είναι
   έτοιμο να ανοίξει σε «Όλοι».
4. Τα pull requests που περιμένουν εσένα:
   https://github.com/eliasgiannakos51-hue/ai-os-saas/pulls
5. Το `docs/NEEDS-FROM-ELIAS.md`: τι περιμένει από σένα, με τη σειρά.

**Δεν υπάρχει ακόμα** εβδομαδιαία σύνοψη που να σου έρχεται μόνη της με
έσοδα, κόστος και περιθώριο.
