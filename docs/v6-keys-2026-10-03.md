# V6 §1.0 — every key, what it does, whether it works

Written 2026-10-03, for `docs/v6-master.md` §1.0. A record of one day for
the parts marked with a date; the inventory itself is not copied here, it
is produced by the code.

## 1. The inventory lives in code, and is checked against code

- **The table:** `src/lib/ai/providers/key-inventory.ts` — ten entries:
  variable names, the role the owner gave each key, the files that read
  it, what is missing, and the free call that tests it.
- **The gate:** `scripts/tests/key-inventory.test.mjs` holds `readBy` to
  `src/` both ways. A key marked "read by nothing" that gains a reader, or
  a listed reader that stops reading, turns the build red. Its sidecar
  `scripts/tests/key-inventory.mutation.mjs` breaks it eleven ways and
  requires each to be caught (11 of 11 on 2026-10-03).
- **The screen:** `/dashboard/system-health`, panel "Provider keys"
  (`src/components/system-health/key-checks.tsx`). Without a click it
  shows, per key, whether it is set and whether any code reads it. "Check
  keys" calls `/api/system-health/keys`
  (`src/app/api/system-health/keys/route.ts`): one free read per provider
  (a model list or an account call, never a generation), owner only,
  names and statuses only.

**Run it in production, not here.** This build environment has none of
the keys (checked 2026-10-03: all ten names unset), so no key has been
checked yet. The first real answer comes from pressing the button on the
deployed page.

## 3. Variable names the check expects

The inventory reads exactly these names: `ANTHROPIC_API_KEY`,
`OPENAI_API_KEY`, `GROQ_API_KEY`, `GOOGLE_API_KEY` (or `GEMINI_API_KEY`),
`DEEPGRAM_API_KEY`, `ELEVENLABS_API_KEY`, `BFL_API_KEY`,
`IDEOGRAM_API_KEY`, `RUNWAYML_API_SECRET`, `VAPID_PRIVATE_KEY`. If a key
sits in Vercel under another name, the panel says "not set" for it — the
fix is to rename the variable in Vercel, not to guess here.

## 5. Keeping the keys safe

- **Server only.** None of these names carries `NEXT_PUBLIC_`, and
  `scripts/tests/client-env-reach.test.mjs` fails the build if a client
  component reads a server variable.
- **Never in a response.** The key-check route returns names and status
  words; `key-inventory.test.mjs` feeds it a provider that echoes the key
  back and requires the result not to contain it.
- **Never in the repo.** `.env.local.example` carries names with empty
  values.
- **Rotation:** any key that was ever pasted into a chat, an issue or a
  log should be rotated at the provider and replaced in Vercel.

## 6. Spending limits — where each provider sets them

**Not verified on the providers' own pages on 2026-10-03** (several are
blocked from this environment). Written from general knowledge, to be
confirmed by the owner when setting them:

| Provider | Where | Kind |
|---|---|---|
| Anthropic | Console → Settings → Limits | monthly spend limit per organisation/workspace |
| OpenAI | Platform → Settings → Limits / project budgets | budget alerts; hard limits vary by account |
| Google (Gemini) | Google Cloud Console → Billing → Budgets & alerts | alerts by default, not a hard stop |
| Groq | Console → Settings → Billing | depends on plan |
| ElevenLabs | subscription quota | the plan's character allowance is the cap |
| Deepgram, BFL | prepaid credit | the balance is the cap |

The app keeps its own ceiling on top of these: `MAX_DAILY_AI_CALLS` and
the per-account credit reservation (`src/lib/billing/reservations.ts`).
