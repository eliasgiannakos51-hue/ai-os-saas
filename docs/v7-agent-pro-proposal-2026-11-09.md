# Agent Pro — πρόταση για καμβά / 11 πεδία / ομάδες

**ΠΡΟΤΑΣΗ, όχι προδιαγραφή. 2026-11-09.** Η οδηγία 55 (2026-11-04) άφησε αυτά τα
τρία σαν ονόματα, χωρίς καμία περιγραφή — το επιβεβαίωσα με grep σε όλο το
`docs/` και το ιστορικό, και με έναν αφιερωμένο Explore υποπράκτορα: μηδέν
αποτελέσματα πέρα από το ίδιο μου το terse σημείωμα. Ο ιδιοκτήτης μου ζήτησε
να γράψω εγώ μια πρόταση με βάση το υπάρχον εργαλείο Agent, για να την εγκρίνει
ή να τη διορθώσει — όχι να χτίσω κάτι σιωπηλά πάνω σε μάντεμα.

Κάθε ισχυρισμός παρακάτω λέει αν είναι ΜΕΤΡΗΜΕΝΟ (υπάρχει ήδη στον κώδικα,
με αρχείο:γραμμή) ή ΠΡΟΤΕΙΝΟΜΕΝΟ (δική μου πρόταση, να εγκριθεί).

## 1. Τα «11 πεδία» — ΜΕΤΡΗΜΕΝΟ εύρημα

Το standalone εργαλείο Agent (`src/lib/agents/agent-config.ts`) έχει σήμερα
ακριβώς αυτά τα ρυθμιζόμενα πεδία:

**`AgentDraft` (7):** `name`, `description`, `prompt`, `scheduleCron`,
`timezone`, `deliveryMethod`, `deliveryTarget`
(`agent-config.ts:99-108`).

**`AgentConfigJson` (4 ρυθμιζόμενα από τον χρήστη):** `needsWebSearch`,
`depth`, `outputFormat`, `language`
(`agent-config.ts:61-97`· το `batchOptOut` και το `builderSummary` υπάρχουν
αλλά δεν είναι κάτι που ρυθμίζει ο χρήστης σε φόρμα — το πρώτο είναι
λειτουργίας, το δεύτερο είναι echo της δημιουργίας).

7 + 4 = **11.** Αυτό ταιριάζει ακριβώς με τον αριθμό «11 πεδία» της οδηγίας
55 — πολύ πιθανό να εννοούσε ΑΥΤΟ το σχήμα, παρουσιασμένο αλλιώς (καμβάς) στο
Pro, όχι ένα νέο, άγνωστο σχήμα 11 πεδίων. Η παλιότερη υπόθεση session ότι το
Agent tool έχει «13 πεδία» μετρούσε πιθανότατα τα nested/db-only πεδία
(`UserAgent`, `agent-config.ts:111-128`, που περιλαμβάνει `status`,
`consecutive_failures` κ.λπ. — αυτά δεν τα ρυθμίζει ο χρήστης, άρα δεν είναι
«πεδία» με την έννοια μιας φόρμας).

**ΠΡΟΤΕΙΝΟΜΕΝΟ:** τα 11 πεδία του Agent Pro = αυτά τα ίδια 11, όχι νέα. Ο
καμβάς είναι νέος τρόπος να τα δεις/αλλάξεις, όχι νέο περιεχόμενο.

## 2. Ο καμβάς — ΠΡΟΤΕΙΝΟΜΕΝΟ, με υπαρκτό προηγούμενο

Αυτό το προϊόν ΕΧΕΙ ΗΔΗ έναν καμβά — απλά όχι για Agents. Τα Automations
Pro (οδηγία 55 Κομμάτι 1, `src/lib/automations/boxes.ts`) είναι ήδη «μια
σειρά από κουτιά»: start/read/ai/condition/approval/action, κάθε κουτί ένα
πράγμα που αλλάζεις με λόγια, έως `MAX_BOXES = 8` (`boxes.ts:21`), σχεδιασμένο
και χτισμένο (`src/components/automations/flow-boxes.tsx`).

**ΠΡΟΤΕΙΝΟΜΕΝΟ: ο καμβάς του Agent Pro είναι το ΙΔΙΟ σχήμα, όχι κάτι
ελεύθερο 2D με γραμμές/κόμβους.** Δηλαδή όχι ένα νέο, γενικό εργαλείο
σχεδίασης γραφημάτων (μεγάλο ρίσκο, μήνες δουλειάς, νέο state machine), αλλά
8-11 κουτιά σε σειρά, ένα ανά πεδίο ή ομάδα πεδίων:

1. Όνομα + περιγραφή (ένα κουτί)
2. Η δουλειά (`prompt`) — το μεγάλο κείμενο
3. Πρόγραμμα (`scheduleCron` + `timezone`)
4. Βάθος/κόστος (`depth`) — Light/Standard/Deep, όπως είναι ήδη στο απλό tool
5. Web search ναι/όχι (`needsWebSearch`)
6. Μορφή απάντησης (`outputFormat`)
7. Γλώσσα (`language`)
8. Παράδοση (`deliveryMethod` + `deliveryTarget`)

Αυτό είναι μία αλλαγή *παρουσίασης* πάνω στο ήδη υπάρχον, ήδη δοκιμασμένο
`validateAgentDraft`/`normaliseAgentConfig` — καμία νέα στήλη, καμία νέα
migration, risk μικρό. Η εναλλακτική (ελεύθερος καμβάς, σύρε-άφησε κόμβους)
θα ήταν νέο προϊόν μέσα στο προϊόν· δεν το προτείνω πρώτο.

## 3. «Ομάδες» (teams) — ΠΡΟΤΕΙΝΟΜΕΝΟ, το πιο ανοιχτό σημείο

Δεν υπάρχει ΚΑΝΕΝΑ ίχνος «ομάδας» πουθενά στο σχήμα (`UserAgent` δεν έχει
`team_id` ή αντίστοιχο) ή στα docs. Τρεις πιθανές έννοιες, πολύ διαφορετικό
κόστος η καθεμία — αυτό θέλω να διαλέξεις, όχι να το μαντέψω:

- **Α. Ομάδα = φάκελος.** Απλή ετικέτα/ομαδοποίηση πρακτόρων στη λίστα
  (π.χ. «Πωλήσεις», «SEO»). Μικρό: μία νέα στήλη, φίλτρο στη λίστα. Καμία
  αλλαγή στο πώς τρέχουν.
- **Β. Ομάδα = κοινή παράδοση/credentials.** Πολλοί πράκτορες μοιράζονται
  ένα κανάλι παράδοσης (ίδιο Slack/email group) χωρίς να το ξαναγράφει ο
  καθένας. Μεσαίο: αγγίζει το ήδη προσεκτικό μοντέλο ιδιοκτησίας παράδοσης
  (`agent-config.ts:191-218` — «ο ΜΟΝΟΣ στόχος που επιτρέπεται είναι ο δικός
  σου»), άρα χρειάζεται να ξαναδιαβαστεί προσεκτικά πριν χτιστεί.
- **Γ. Ομάδα = πράκτορες που μιλούν μεταξύ τους** (ο ένας διαβάζει την
  έξοδο του άλλου, αλυσίδα). Μεγάλο: νέος runner-συντονισμός, νέα επιφάνεια
  για prompt injection ανάμεσα σε πράκτορες του ΙΔΙΟΥ λογαριασμού (ήδη
  μελετημένο μόνο για ξένο περιεχόμενο από το web, όχι μεταξύ πρακτόρων).

**ΠΡΟΤΕΙΝΟΜΕΝΟ να ξεκινήσουμε από το Α** (φάκελος/ετικέτα) — είναι το μόνο
που δεν αγγίζει ασφάλεια ή χρέωση, και είναι η βάση που θα χρειαστούν τα Β/Γ
αργότερα αν τα θέλεις.

## 4. Τι ΔΕΝ προτείνω τώρα

Καμία αλλαγή στο standalone Agent tool (το απλό, υπάρχον) — το Pro είναι
νέο ΠΑΡΑΘΥΡΟ πάνω στο ίδιο σχήμα και τον ίδιο runner, πίσω από ένα δικό του
switch (`isFeatureOn`), ακριβώς όπως το Automations Pro ήταν νέο παράθυρο
πάνω στο ίδιο flow schema.
